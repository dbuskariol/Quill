# Quill distribution and updates

Sparkle 2.10.0 is pinned through Swift Package Manager. It owns native update progress, verification, errors, installation and relaunch. Quill observes check availability and exposes automatic check/download preferences. Automatic checks, downloads and system profiling default off. Signed appcasts and verification before extraction are required. No updater starts unless the build contains an HTTPS `SUFeedURL` and a valid 32-byte base64 `SUPublicEDKey`. There is intentionally no example feed in the app. The default build makes no update connection.

External inputs still needed: the final Quill appcast/archive hosting URL; a Quill-specific Ed25519 key managed by its release owner; Developer ID Application identity/team; and an Apple notarization credential profile. None are inherited from Reccy. Do not commit private keys, certificate passwords or notarization credentials. The owner must choose key storage, backup/recovery and rotation policy before generating keys. Sparkle's official `generate_keys` and `generate_appcast` tools are included in the resolved package artifact. They have not been invoked and no credentials have been created.

`script/prepare-release.sh` requires explicit `QUILL_RELEASE_DIR`, `QUILL_DEVELOPER_ID`, `QUILL_UPDATE_FEED`, and `QUILL_UPDATE_PUBLIC_KEY`. It runs the verification gate, creates a universal app, inserts the supplied public configuration in the staged copy, signs nested Sparkle components inside out, signs the app with hardened runtime, verifies signatures, and creates a notarization ZIP. The output directory must be new and external to the repository. This workflow is prepared, not accepted against an actual Developer ID artifact. Signing timestamps contact Apple's signing service; running this script requires the owner's release configuration. It does not submit notarization or publish.

After separately authorized notarization, use `xcrun notarytool submit <zip> --keychain-profile <Quill profile> --wait`, inspect the success report, staple the app, and verify with `codesign --verify --deep --strict` and `spctl --assess --type execute`. Create the final update archive only after stapling. Use the Quill signing key with Sparkle's appcast tooling to sign both archive and feed. Review the appcast's minimum OS, build number, archive URL, signature and release notes before publishing. Feed configuration may not be edited in an already signed application.

Acceptance must exercise an older signed Quill install against a private staging feed: successful update and relaunch, declined update, offline/TLS errors, malformed appcast, bad metadata/archive signatures, unsupported OS, downgrade rejection, interrupted download, and install permission failure. No production install replacement is authorized here. Verify user libraries, drafts and revisions survive each path; force a failed migration and confirm the prior file remains intact. Keep the previous notarized build and library backup available for manual rollback. This build remains library schema v1 and never auto-downgrades a newer schema.

Development uses only external DerivedData. It does not replace `/Applications/Quill.app`. TCC permission grants for ad-hoc binaries can change across rebuilds and do not establish distribution identity acceptance. Test login registration from a stable installed signed bundle; the development path currently reports service not found.

Official references: https://sparkle-project.org/documentation/ and https://sparkle-project.org/documentation/customization/.
